# Pull Request Coverage Reports

## Goal and scope

Make the Python coverage report generated by CI easy to inspect from a pull request. Use the report to see which behavior still needs an executable example. Start with [the current coverage step](../../../.github/workflows/ci.yml), [pytest configuration](../../../pyproject.toml), and [the reference on coverage](https://bits.logic.inc/p/ai-is-forcing-us-to-write-good-code).

## Milestones

1. With the isolated app running, run `bash scripts/compose.sh exec -T app uv run pytest --cov=app --cov-config=/workspace/pyproject.toml --cov-report=term-missing --cov-report=xml tests`. Record the commit, exclusions, reported line coverage, and report path. Verify from the Compose mounts which path the CI runner can read.
2. Add a workflow artifact for the existing coverage report and a brief job summary if the report is hard to find. Give the artifact a clear name and bounded retention. Keep the current test result as the job's source of pass or fail. Publish results from a representative PR and confirm a reviewer can match a missing line to the tested commit.
3. Review baseline reports before deciding on enforcement. Consider a narrowly scoped threshold for a critical area if repeat measurements show it will detect a real regression. Record why any threshold or exclusion is chosen.

## Acceptance and pull requests

- **Coverage visibility PR.** Verify CI publishes a nonempty XML report for a green test run and a reviewer can locate it from the workflow run. Exercise the missing-report path with a temporary fixture. A failed pytest command must remain visible as a failure and a missing XML file must produce an actionable diagnostic. Test any new executable CI tooling in its corresponding job.
- **Optional coverage threshold PR.** Follow the visibility PR only if evidence supports a stable threshold. Record the baseline and prove a scratch case below the proposed threshold fails while the baseline passes.

If publishing fails, separate the pytest result from artifact errors. Check the validated mount, path, and XML contents before retrying. Discard stale scratch reports between runs. Revert publishing or the optional threshold independently of the underlying test suite.

## Worktree and recovery

Run commands from this plan's dedicated worktree. Record `git status --short` and `git rev-parse HEAD` before starting. When the work needs Django and PostgreSQL, run `bash scripts/init-worktree-env.sh` and `bash scripts/compose.sh up --build -d`. Confirm `app` is listed by `bash scripts/compose.sh ps --status running --services`. If startup is interrupted, inspect `bash scripts/compose.sh ps -a` and follow the [Compose troubleshooting guide](../../../.agents/skills/create-worktree/references/compose-troubleshooting.md) before retrying in the same worktree.

Run `bash scripts/check-docs.sh` after staging documentation changes. Use the full [pre-push validation](../../../.agents/skills/create-pr/SKILL.md#3-validate-before-pushing). Confirm Ruff formatting, Ruff lint, and pytest completed.

If the hook reports `Skipping final validation`, address the stated cause. If the tracked `compose.yaml` is accidentally missing, confirm the deletion with `git status --short` and restore the file from the intended commit. If the root `.env` is missing or has no project name, run `bash scripts/init-worktree-env.sh` for a fresh worktree. For a previously initialized worktree, recover its original project name and local credentials before retrying so its database volume remains attached. Stop if the original settings cannot be recovered. Once the configuration is valid, start the intended stack as described above, confirm `app` is running, and rerun the hook.

After pushing, use `bash scripts/stop-local-stack.sh` for a path-bound Compose project. For a legacy or directory-default project rejected by the helper, verify that the project belongs to this worktree before running `bash scripts/compose.sh down` from the same checkout. Both paths retain the database volume. See the [post-push cleanup procedure](../../../.agents/skills/create-pr/SKILL.md#4-push-the-branch).
