# Core Beliefs

- **Keep game rules independent of infrastructure.** Put move validation and state transitions in the framework-independent game rules service so every caller uses the same rules. See the [architectural boundaries](../../ARCHITECTURE.md#architectural-boundaries) and the [game domain design](../domains/game/context-designs.md#state-transition-contract).
- **Keep responsibilities at their layer boundaries.** HTTP handlers translate requests and responses through DTOs. Application services coordinate use cases and transactions. Repositories own ORM access, and database constraints protect persisted state. See the [architecture code map](../../ARCHITECTURE.md#code-map), [API rules](../../.codex/rules/api.md), and [database schema](../domains/game/db-schemas.md).
- **Validate external input and protect credentials.** Check incoming data at the boundary that accepts it, keep credentials out of source and logs, and bind values separately when explicit SQL is required. See the [security rules](../../.codex/rules/security.md) and [HTTP security guidance](../../ARCHITECTURE.md#cross-cutting-concerns).
- **Isolate development and verify behavior where it runs.** Give each worktree its own Compose project and database volume. Cover service behavior with tests and run validation in the worktree's containers. See [environment setup and testing](../../AGENTS.md#environment-setup-and-testing) and the [worktree isolation reference](../../.agents/skills/create-worktree/references/multi-session-worktrees.md).
- **Keep design documents tied to evidence.** Update the relevant English design or contract when behavior changes. Record what was checked against implementation and tests in the [design index](index.md), and identify any remaining verification work. See the [feature documentation guide](../../.agents/skills/document-feature/SKILL.md).
